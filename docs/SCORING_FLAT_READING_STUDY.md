# 「读平也通关」研究：原因与修法对比

> **状态：研究报告，供决定修法用。** 没有改任何正式评分代码（Swift `PinYintone/Core/Audio`、
> Kotlin `android/core/src/main`）、`CLAUDE.md` 和 `testdata/scoring/golden.json`。
> 实验代码在 `android/scoring-study/`（复用 `:core` 的正式实现作基线，候选修法只在实验里实现）；
> 全部原始数字在 `android/scoring-study/results/results.md`，本文的数都引自那里。
> 复现方法见文末「附：复现」。

## 结论先看

- **推荐：先上 C2「走势幅度闸门」，DTW 与 0.5 通关线都不动。**
  词里含二 / 三 / 四声时，学习者 clean 后的**原始 Hz** 换算成半音，若 P90 − P10 < **2 个半音**
  就判不通关（与平调闸门同一种「DTW 之外的闸门」）。全一声的词与 1+5（一声 + 轻声）不管。
- 关键数字（非全一声词；括号外是合成集 · 理想轮廓参照，括号里是 TTS 真实音频 · TTS 参照、有声帧 ≥ 20）：

  | | 现行 | **C2（推荐）** | Bs2n + C2（可选第二步） |
  |---|---|---|---|
  | 读平被拦下 | 33%（49%） | **95%（98%）** | 95%（98%） |
  | 正确读法通关 | 97%（91%） | **97%（89%）** | 98%（86%） |
  | 两个字都读错被拦下 | 54%（62%） | 59%（71%） | 86%（80%） |
  | 错一个字被拦下 | 22%（36%） | 26%（44%） | 45%（53%） |
  | 一声词（含平调闸门） | — | **逐位不变** | 逐位不变 |
  | 已有分数 `dtwScore` | — | **逐位不变**，只有 `grade` 变 | 非一声词的分数全变 |

- `t4t4_read_flat`：现行 0.311 通关；C2 下 DTW 仍是 0.311，但走势跨度（P90−P10）不到 0.01 个半音，被闸门拦下。
- **「两层原因」只解释了 golden 里那条完全恒定的 220 Hz。** 真实的读平总有一点漂移和抖动，
  这时主因是第三层：**归一化是尺度不变的**，1 个半音的漂移与 10 个半音的四声被拉成同样大小的曲线。
  走势压到正常的 10%（跨度 0.9 半音，听感上就是平的），现行算法仍有 93–99% 通关——
  改 DTW 分母或加带宽（A、B 族）都解决不了，只有看原始幅度的 C 能解决。
- **不建议现在改 0.5**：分数本身可分（合成集 AUC 0.97），最优阈值在 0.22–0.36 之间，
  但一降阈值，一声词就大量误判（TTS 参照下降到 0.35 时一声词读平通关率从 97% 掉到 38%）；
  要等真实录音校准，并且一声词须单独处理。
- **影响面比原先以为的大**：不只四声，所有非一声组合读平都有约 2/3 通关；
  历史口径（schemaVersion ≤ 3，无归一化下限）也有约一半通关，不是从 v4 才开始的。

---

## 1. 问题

四声 + 四声的词读成 220 Hz 平调（`testdata/scoring/golden.json` 的 `t4t4_read_flat`，
备注写的是「应不通关」），Swift 版得分 0.311、`grade = good`、判通关。
Android 版逐位照搬，两端行为一致。线上 iOS 学习者现在就受影响。

## 2. 原因

### 2.1 拆解 t4t4_read_flat

| 量 | 值 |
|---|---|
| 参照（理想轮廓 4+4）有声帧 m | 48 |
| 学习者有声帧 n | 88（n/m = 1.83） |
| 学习者原始 Hz | 218.0–223.1，sd = 0.72 Hz |
| 归一化除数 | 下限 218.4 × 0.03 = 6.55 Hz（sd 远小于下限） |
| 归一化后学习者 | −0.06 … 0.72，平均 \|z\| = 0.03（几乎全是 0） |
| 参照平均 \|z\| | 0.83（参照均值恰为 0） |
| DTW 总代价 D / 路径步数 W | 36.96 / 119 = **0.311** |

机制：归一化下限把读平的录音压成一串 ≈ 0 的数，而 0 正是任何参照曲线的均值，
参照从高到低穿过 0 的那一帧（第 34 帧，z = 0.02）跟它们几乎零代价。
最优路径 119 步里有 **71 步**是「参照停在同一帧、学习者往前走」，**72 个学习者帧全停在第 34 帧上**，
这 71 步代价合计只有 2.44（每步 0.034）。分母是路径步数，这些近乎免费的步数把总代价摊薄了。

反事实（同一段录音、同一参照，只换一个条件，用现行 DTW 计分）：

| 条件 | 学习者长度 | 归一化 | 分数 |
|---|---|---|---|
| 现状 | 88 帧 | 带下限 | **0.311** |
| 去掉长度因素 | 重采样到 48 帧 | 带下限 | 0.540 |
| 去掉下限（纯 z-score） | 88 帧 | 无下限 | 0.486 |
| 两者都去掉 | 48 帧 | 无下限 | 0.786 |

两个因素合计把分数从 0.786 压到 0.311（−0.475）。按 Shapley 平均分摊：
**长度（路径步数稀释）−0.265，占 56%；归一化下限 −0.211，占 44%。** 两层推测都成立，大致各占一半。

长度扫描（同一条读平序列线性拉伸）：

| n/m | 0.5 | 0.75 | 1 | 1.25 | 1.5 | 1.83 | 2 | 2.5 | 3 |
|---|---|---|---|---|---|---|---|---|---|
| 现行分数 | 0.740 | 0.738 | 0.540 | 0.462 | 0.354 | 0.311 | 0.297 | 0.254 | 0.226 |

学习者比参照长 1.25 倍就过线。理想轮廓参照每个字只有 24 帧（≈ 0.19 s），
真实录音普遍更长，所以这条路径在实际使用里很常见。
注意即使等长也只有 0.540，离 0.5 只差 0.04——等长并不安全。

### 2.2 第三层（真实录音里的主因）：归一化尺度不变

golden 里那条是**完全恒定**的合成音（sd 0.7 Hz，约 0.06 个半音）。人读平不会这么平：
总有 0.3–0.5 个半音的慢漂移和抖动，往往还有 1 个半音左右的句调下倾。
下限是均值的 3%（≈ 0.5 个半音），**超过它的起伏都会被归一化放大成满量程**。

读平 + 整词线性漂移（合成，非一声词，理想轮廓参照，长度 1×；括号内为 2×）：

| 漂移（半音） | −3 | −2 | −1 | −0.5 | 0 | +0.5 | +1 | +2 |
|---|---|---|---|---|---|---|---|---|
| 归一化后峰峰值 | 3.36 | 3.32 | 2.52 | 1.89 | 1.76 | 1.98 | 2.55 | 3.43 |
| 现行通关率 | 43%（60%） | 42%（61%） | 66%（73%） | 67%（83%） | 70%（90%） | 65%（85%） | 54%（72%） | 32%（50%） |

（参照归一化后的峰峰值约 3.5。）1–2 个半音的漂移就被拉到和真实声调一样大。

正确读法按比例压缩走势（0 = 平，1 = 正常；括号是走势跨度 P90−P10）：

| 走势比例 | 0（0.6 半音） | 0.1（0.9） | 0.2（1.6） | 0.3（2.3） | 0.5（3.7） | 1（7.0） |
|---|---|---|---|---|---|---|
| 现行，1× | 74% | **98%** | 100% | 100% | 100% | 98% |
| 现行，2× | 88% | **99%** | 100% | 100% | 100% | 97% |
| B20，1× | 48% | 95% | 98% | 98% | 98% | 97% |
| A4，1× | 51% | 94% | 98% | 96% | 94% | 92% |

**只要形状对，幅度小到 0.9 个半音也通关**；所有只改 DTW 的修法都一样，
因为它们看到的是同一条归一化后的曲线。这与当初给一声词加走向闸门的理由完全相同
（`docs/LEVEL_TONE_SCORING.md` 第五节：「z-score 是尺度不变的……不是调参能解决的」），
只是方向反过来：一声词怕「该平却动了」，其余声调怕「该动却没动」。

### 2.3 问题有多广（现行算法）

合成集，非一声词，两种参照合并来看大致相同（理想轮廓 / TTS 整形）：

| 读法 | 通关率（理想轮廓参照） | 通关率（TTS 参照） |
|---|---|---|
| 正确（自然语流：半上、变调） | 97% | 98% |
| 读平 | **67%** | **66%** |
| 错一个字的调 | 78% | 73% |
| 两个字都读错 | 46% | 43% |

**按长度**（理想轮廓参照，通关率）：

| 长度比 | 0.5× | 0.75× | 1× | 1.5× | 2× | 3× |
|---|---|---|---|---|---|---|
| 读平 | 53% | 63% | 64% | 71% | 76% | 77% |
| 两个字都错 | 37% | 39% | 43% | 45% | 51% | 58% |

越慢越宽松：读得慢的学习者更容易「错了也过」，这本身是一种对语速不公平。

**按声调组合**（理想轮廓参照，读平通关率，长度 ≤1× / ≥1.5×）：
主体是降调的组合几乎全过——4+3 100% / 100%、4+4 89% / 100%、1+4 89% / 100%、1+3 78% / 100%；
以升调开头或收尾的少——2+1 0% / 6%、3+1 0% / 17%、2+2 28% / 22%。
原因是 1–1.5 个半音的自然下倾被放大成一条下坡，正好像降调。

**读错调**：现行算法看的是整词的大致走向，不分字。例如目标 4+4，读成 1+3、1+4、4+3 时都 100% 通关
（高平接低调，整体也是「下来」）。完整混淆矩阵见 results.md。
这一点任何修法都只能部分改善（见第 5 节），根本上需要按音节对齐，而工程里没有经过验证的音节对齐（CLAUDE.md「界面」）。

**一声词**：现有行为正常（读平 100% 通关；读错时被拦 64%，其中下滑由平调闸门拦）。

**历史口径**：v1–v3（无归一化下限）在同一合成集上读平通关 50%（TTS 参照 52%），v4 起 67%。
所以下限让问题**变重**了，但问题不是 v4 才有的。

（与 iOS `SpeechService` 同一套：重平滑 → 去下倾 → 向理想轮廓混合 → 矛盾校验 → 归一化）。
30 个词都没有判矛盾，没有回退理想轮廓。

过不了 0.15 阈值），有声帧中位数只有 25，35% 的原音不到 20 帧，常常只提到一个字。

所以 TTS 组的表都给「有声帧 ≥ 20」的口径，绝对通关率比合成组低，**看各修法之间的相对差别**。

模拟器数据目录里的 `PinYintone.sqlite` 只有分数、没有 F0；仓库与测试资源里只有合成的对照 WAV。
没有查询或连接线上数据库。需要什么数据、怎么取，见第 7 节。

## 4. 候选修法

| 编号 | 做法 |
|---|---|
| BASE | 现行：总代价 ÷ 最优路径步数，≤ 0.5 通关 |
| A1 / A2 / A3 | 同一条路径，分母改为参照长度 m / max(m, n) / m + n |
| A4 / A5 | 同一条路径，每个参照帧只算一票（对齐到它的学习者帧取平均，再对参照帧平均）/ 双向都这样算取较大者 |
| B0 / B10 / B20 | 学习者有声序列线性重采样到参照长度，再做 DTW（不限 / Sakoe-Chiba 半宽 10% / 20%），÷ 路径步数 |
| Bs2 | 重采样后加斜率限制：连续横步或竖步各不超过 2 步 |
| …n | 只对含二 / 三 / 四声的词换算法，全一声的词仍用现行 DTW（为了保住一声词现有行为） |
| C2 / C3 / C4 | 走势幅度闸门：词里含二 / 三 / 四声时，clean 后原始 Hz 相对中位数的半音，P90 − P10 < 2 / 3 / 4 半音即不通关 |
| D | 组合：B10 + C2、B20 + C2、B20n + C2、Bs2n + C2；以及阈值改为 0.35 的两种 |

所有修法都保留现有平调走向闸门（全一声、首末下滑 > 3 半音）。

### 5.3 对照用例

`t4t4_read_flat`：A1 0.77、A4 0.72、B0 0.54、B10 0.63、B20 0.55、Bs2 0.74 都翻到不通关；
A2 0.42、A3 0.27 仍通关；C2 / C3 / C4 都是闸门拦下（DTW 仍 0.311）。

其余用例：一声词三条正确读法、二声 / 四声 / 三声 / 2+4 带间隔全都继续通关，`t1t1_falling` 继续被平调闸门拦下。
例外：`t1t1_tts_declining`（一声带句调下倾）在 A1 下 0.88、B10 下 0.51 变成不通关，
在阈值 0.35 下也不通关；`…n` 系列与 C 系列对它没有影响。

### 5.4 分数可分性与阈值

只看分数、不看闸门，正例 = 正确读法，负例 = 读平 + 两字都错：

| 修法 | AUC 合成（理想 / TTS 参照） | 最优阈值 合成 | AUC TTS 音频 ≥ 20 帧 | 最优阈值 TTS 音频 |
|---|---|---|---|---|
| BASE | 0.971 / 0.954 | 0.22 / 0.24 | 0.887 | 0.31 |
| A1 | 0.976 / 0.956 | 0.33 / 0.44 | 0.900 | 0.43 |
| B10 | 0.982 / 0.978 | 0.30 / 0.36 | 0.893 | 0.45 |
| B20 | 0.980 / 0.967 | 0.24 / 0.26 | 0.895 | 0.29 |
| Bs2 | 0.983 / 0.974 | 0.28 / 0.35 | 0.906 | 0.34 |

各修法的可分性差不多（AUC 只差 0.01–0.02），差别主要在**分数落在 0.5 的哪一侧**。
所有方法的最优阈值都在 0.5 以下，说明 0.5 偏宽——但降阈值要付出一声词的代价（见 6.4）。

## 6. 逐项回答

### 6.1 A 族（改分母 / 参照帧平均）

- **读平 / 读错调**：A1 拦下读平 77–81%，但大部分来自长录音被罚（3× 时读平 0% 通关）；
  走势比例 0.1 时 A4 仍 90–94% 通关——**尺度不变的问题原封不动**。A2 / A3 几乎无效（A3 更宽松）。
- **正确读法误判**：A1 在 TTS 参照、3× 长度下正确读法只有 74% 通关；A4 / A5 余量为负。
- **一声词**：A1 在 TTS 参照下一声词读平通关率 97% → 29%，`t1t1_tts_declining` 0.38 → 0.88。**破坏一声词。**
- **0.5**：A1 的分数尺度整体变大，要重新校准（最优 0.33–0.44）。
- **音域 / 语速**：音域公平；A1 对慢读的人明显不公平（分母不随学习者变长）。
- **复杂度**：A1–A3 两端各改一行；A4 / A5 要回溯整条路径，约 20 行。
- **CLAUDE.md**：DTW 表「路径长度归一化」要改；所有非一声 **与一声** 词分数语义都变。
- **数据**：全部 `dtwScore` 不可与 v6 混合。
- **结论：不推荐。**

### 6.2 B 族（重采样等长 + 带宽 / 斜率限制）

- **读平 / 读错调**：B10、Bs2 读平拦下 64–68%（合成）、85–87%（TTS 音频）；
  两字都错拦下 81–89%，是所有单一修法里最好的；**消除了长度偏差**（各长度档几乎一样）。
  但走势比例 0.1 时仍 85–95% 通关：同样拦不住「形状对、幅度很小」的读平。
  B0（只重采样、不限路径）几乎无效——说明是路径的自由度在「停车」，而不只是长度。
- **正确读法误判**：B20、Bs2 正确 96–98%（合成），余量 0.01–0.05，偏紧；B10 合成余量 −0.07，TTS 音频正确只有 80%。
- **一声词**：B10 在 TTS 参照下一声词读平通关 97% → 38%，Bs2 → 67%，B20 → 78%。
  **必须只对非一声词启用**（`…n` 版本），一声词保持现行才能逐位不变。
- **0.5**：最优阈值 0.24–0.36（合成）/ 0.29–0.45（TTS 音频），要靠真实数据重新校准；不校准的话 B20 / Bs2 在 0.5 下仍偏宽。
- **音域 / 语速**：都公平（语速差异被重采样吸收）。
- **复杂度**：重采样 + 带宽约 20 行；斜率限制要三维状态（约 40 行），两端都得写并补对照数据。
  有一处要注意：重采样是插值，两端 Float 运算顺序须一致，否则对照会漂。
- **CLAUDE.md**：DTW 表要写明重采样与带宽 / 斜率；平调闸门旁注明一声词仍用旧 DTW。
- **数据**：非一声词的 `dtwScore` 全部改变，不可跨版本混合；一声词逐位不变。

### 6.3 C（走势幅度闸门）

- **读平**：拦下 94–95%（合成）、98%（TTS 音频），与长度、音域无关（男 / 女 95% / 95%，0.5×–3× 都是 5–6% 漏判）。
  漏掉的是带 2–3 个半音明显漂移的「读平」——那已经是一条有走势的线，交给 DTW 判。
- **读错调**：基本不管（错两字 54 → 59%）。C 只解决「没有起伏」，不解决「起伏方向错」。
- **正确读法误判**：合成集正确读法跨度最小的是 2+2（P1 2.8 半音）、3+1（P1 2.5）；C2 对它们有 0.5–0.8 半音余量，
  合成正确通关率不变（97%）。C3 已贴近 2+2、3+2 的下沿；C4 合成最差长度档降到 83%，不取。
  走势比例扫描：C2 在比例 0.2（1.5–1.6 半音）时还放过 15–23%，0.3（2.3 半音）放过 54–73%，0.5 以上全放过——
  只拦「基本没动」的，不替 DTW 判「动得不够」。
  **风险**：YIN 漏掉一个字时，只剩一个字的轨迹，跨度可能不足 2 半音（TTS 组的 2+4「学校」、3+2「旅行」就是这样，
  正确读法里 8–25% 跨度 < 2）。不加有声帧门槛时 C2 让 TTS 组正确通关率降 5 个百分点。真实录音的漏检率未知，见第 7 节。
- **一声词**：不适用，**行为逐位不变**（平调闸门照旧）。
- **0.5**：不用动；DTW 分数不变。
- **音域 / 语速**：半音是对数比，与音域无关；P90−P10 与时长无关。
- **复杂度**：两端各约 15 行（中位数、半音、两个分位数），与 `ToneDirectionGate` 同一形态。
- **与禁令 16 的关系（为什么不算扩大平调闸门）**：禁令 16 禁的是把**走向闸门**（「首末下滑 > 3 半音 = 不通关」）
  用到非一声词上——那样会因为二 / 三 / 四声本来就有的大起伏把正确读法判错。C 是另一道闸门，判的方向相反：
  它只在「该有起伏却几乎没有」时拦，**从不因为有起伏而判错**，所以不会造成禁令 16 担心的误伤；
  适用范围也不同（含二 / 三 / 四声的词；全一声词仍只归走向闸门管，1+5 两道都不管）。
  但禁令 16 的理由「其余声调 DTW 处理正常（4+4 实测正确 0.081 / 错误平读 0.933）」本身被本研究推翻了：
  0.933 是等长、无下限时测的，现行条件下 4+4 读平只有 0.311。这句理由要改。
- **CLAUDE.md**：DTW 评分表加一行；禁令 15 的「必须传原始 Hz」扩到新闸门；禁令 16 改写理由；
  新增禁令（不得喂归一化序列、不得改成固定 Hz、不得扩到全一声词）；记录版本加 v7 说明。
- **数据**：`dtwScore` 逐位不变，只有 `grade` / `passed` 变；v7 起「`grade = fail` 且 `dtwScore ≤ 0.5`」
  对非一声词表示幅度闸门、对全一声词表示走向闸门，按声调可区分。

### 6.4 D（组合）与阈值

- **Bs2n + C2 / B20n + C2**：读平同 C2（95%），两字都错拦下从 59% 提到 78–86%，错一字 26% → 38–48%，
  一声词逐位不变，长度偏差消失。代价：正确读法余量只剩 0.01–0.05（合成）、TTS 音频正确通关 86–87%（比 C2 低 2–3 点）；
  非一声词分数语义全变；实现量是 C 的 3–4 倍。
- **降阈值到 0.35**：错调拦下明显变好（错两字 84–90%），但 TTS 参照下**一声词读平通关率掉到 38%**，
  `t1t1_tts_declining` 不通关；正确读法通关降到 89–94%（合成）、75%（TTS 音频）。
  如果以后要降，必须一声词单独保留 0.5（或单独校准），而且只能在有真实录音之后定。

## 7. 推荐方案与理由

**随 schemaVersion 7 上线 C2；B 族与阈值留待真实数据校准后再决定。**

1. C2 针对的就是报告的问题，而且把它解决干净了（读平拦下 33% → 95%，真实音频 49% → 98%），
   对正确读法几乎无副作用（合成 97% → 97%，真实音频 91% → 89%），对长度、音域公平。
2. 不动 DTW、不动 0.5：所有已有分数逐位不变，一声词逐位不变，`golden.json` 现有字段全都不变，只新增字段。
   这与 v5 加平调闸门是同一种改法，两端实现小，对照数据好锁。
3. A / B 族解决不了主因（尺度不变）。B 族的真正价值在**读错调**与**语速公平**，但它要重新校准阈值、
   会改变所有非一声词分数的含义；在只有合成 / TTS 数据、母语者参考音还没录的情况下定这些参数，等于拿 TTS 校准。
   等 20 个母语者参考音到位、有了真实学习者录音后，再用本实验工具重跑 Bs2n / B20n 与阈值，单独作为 v8 决定。
4. 平行要做的一件事：**把走势跨度（半音）写进记录**。现在线上只存了 `dtw_score` 和 `voiced_frame_count`，
   C 的阈值是用合成数据定的；有了这个字段，上线后就能直接看真实学习者正确读法的跨度分布、回头校准 2 半音这条线。

阈值取 2 而不是 3：两者拦读平的效果一样（95% / 95%，真实音频 98% / 98%），
但 3 半音已经贴近 2+2、3+2 正确读法的下沿（TTS 组 3+2 有 58–62% 的正确读法跨度 < 3），2 有余量。

## 8. 还需要哪些真实数据

1. **母语者 20 个词的参考录音（计划中）**：既是新的参照，也是 C 的下沿——母语者正确读法的跨度分布。
   每个词最好 2 位以上发音人、男女各有，按 `testdata/scoring/README.md` 的格式做成 WAV。
2. **学习者真实录音 + 人工标注**：这是校准 C 的阈值、B 族与 0.5 的唯一可靠依据。App 设计上不存录音，
   所以需要单独采集：例如 10–20 位学习者 × 20 个词 × 正常读 / 刻意读平 / 刻意读错各一遍，由老师标「对 / 平 / 错」。
   这涉及知情同意与伦理审查，由研究者决定；采集后放进本地目录，用 `android/scoring-study` 直接重跑。
   如果不能存音频，退一步是在调试构建里导出**逐帧 F0（Hz）**而非音频——足够跑本研究的全部分析。
3. **线上已有的数据（由你决定是否取、由你本人执行，我没有连接）**：只读查询即可，不需要音频：
   - 各词条的 `voiced_frame_count` 分布（判断真实录音会不会像 TTS 那样漏掉一个字，即 C 的主要风险）；
   - 各词条 `dtw_score` 分布与通关率，按 `schema_version` 分层（估计受影响的规模）。

   示例（PostgreSQL，只读）：

   ```sql
   SELECT lexeme_id, schema_version, count(*) AS n,
          percentile_cont(ARRAY[0.1,0.5,0.9]) WITHIN GROUP (ORDER BY voiced_frame_count) AS voiced_p10_50_90,
          percentile_cont(ARRAY[0.1,0.5,0.9]) WITHIN GROUP (ORDER BY dtw_score)          AS dtw_p10_50_90,
          avg(CASE WHEN grade <> 'fail' THEN 1 ELSE 0 END)                                AS pass_rate
   FROM training_sessions
   WHERE result_status = 'valid_result'
   GROUP BY lexeme_id, schema_version
   ORDER BY lexeme_id, schema_version;
   ```
   注意线上 `training_sessions` 里有约 10 条之前误传的合成测试记录（schema_version 6、2026-10-13），取数时排除。
4. **上线后**：v7 记录里的走势跨度字段，按词条看正确读法（`grade` ≠ fail 且未被闸门拦）的跨度 P1 / P5，
   确认 2 半音有余量。

## 10. 局限

- 学习者全部是合成的或 TTS 的，没有一条真实学习者录音；绝对数值（尤其通关率）只供相对比较，
  阈值都需要第 8 节的数据再校准。
- 合成正确读法用五度值描述，和理想轮廓同源；正确通关率对现行算法可能偏乐观。
- 4+5 的理想轮廓把轻声画成中平（195 Hz），而四声后的轻声实际是低调，所以理想轮廓参照下 4+5 正确读法本来就偏差；
  3+1 正确读法（半上）对 214 的理想轮廓也只有 78% 通关。这是参照的问题，与本次修法无关，换母语者参考音后应消失。
- TTS 参照本身也有漏检（「现在」「学校」只有 23 个有声帧），整形后的参照比理想轮廓短。
- 单音节词与 3+3 没有测（语料里没有）。
