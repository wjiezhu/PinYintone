## 一、研究设计

### 1. 三阶段降级为「可选自测」
`pretest / training / posttest` 不再是强制序列，改为**用户主动发起**的自测。

- 论文是《…设计与**可用性**研究》，需求也写明用于「上线后的**自然使用**」，
  前后测裸测本就不服务于这个设计。
- 自选自测存在**自选择偏差**，与 `feedbackMode` 同类（CLAUDE.md 禁令 10），
  **不得当作前后测证据**。

### 2. 词集重叠：接受，改为如实记录
自由选词后无法保证训练词与测试词不重叠，故不再限制选词，
而在自测记录里带 `prior_practice_count`（该词此前练过几次）。
「练过 N 次后自测得分」本身是可用性研究里有意义的数据。

### 3. 词卡 = 「推荐练习」入口
> **已被取代（2026-10-13）**：普通练习不设机会数、不发积分，说没说对都可以一直重录、
> 随时换词。下面的「每词 3 次机会、说对得分」**不再是现行行为**；积分整体关闭（第 12 条）。
> 自测仍是裸测、每词录一次自动过。「说对 = `grade != fail`」与「技术失败不算一次」两条仍然成立。

可随时退出、也可自己挑词，因此不构成需求禁止的「统一训练任务」。

- 练习模式：每词 3 次机会，说对 → 积分 → 下一词；3 次用完自动过。
- 自测模式：纯裸测，每词录一次自动过，**不发积分、不设机会数**，
  隐藏分数/积分/机会计数。词卡 UI 共用。
- 「说对」判定 = `grade != fail`，**含平调走向闸门**。只看 DTW ≤ 0.5
  会让一声词掉调也拿分，绕开闸门。
- **技术失败不消耗机会**：没录上不是发音问题（CLAUDE.md 禁令 9）。

### 4. 教师看板与班级码：冻结归档
需求全文未提及，新研究对象是自然使用的个人用户而非班级。
代码保留、不再开发，新表不为其做查询。

## 二、数据

### 5. 新旧数据物理分表
新建 `research_*` 表，旧表冻结只读。
不选「同表加 dataset 标记」：这个项目里「每个查询都记得加过滤条件」
已经失败过——技术失败的哨兵 `-1` 在 `export.sql` 里筛了、在 `teacher.py` 里
忘了，导致班级均分虚高 4 倍（PR #51）。物理分表是忘不掉的。

### 6. 轻声编码换算
App 内部与语料用 `5`，研究库 `citation_tones` 用 `0`。
差异**静默**：原样写入不报错，只有取数时才发现值对不上，而语料有 3 个轻声词。
换算收在 `ResearchToneCoding`（Swift）与 `tone_coding.py`（Python）两处，
两端各有测试互相对照。

### 7. 词条版本编号 ≠ 稳定编号
`research_lexemes` 主键是**版本级**编号，词条内容或示范一改就换新。
曾把 `Lexeme.id` 直接当版本编号上报，导致**外键全部悬空**（6 处，PR #53 修）。
`research_lexicon.json` 是两端共用的唯一真源；未知词条返回 nil，
**不回退成稳定编号**——回退只会重新制造悬空外键。

### 8. ⚠ 偏离字典：三列放宽为可空
`target_realization` / `source_detail` / `reference_audio_version`
在字典 §6 中必填，这里改为可空。

词条在教师核对前确实没有这些信息，而填「待核实」之类的字符串会
**看起来像数据**，混过 `IS NOT NULL` 筛选、被当成已核实的出处。
NULL 才是「不知道」的诚实编码。约束改为 **`approved` 时三列必须齐全**，
种子脚本强制。

### 9. 研究接口的时间格式
研究接口一律 ISO8601 带时区字符串；**服务端拒收数字**（422）。

iOS 默认 `JSONEncoder` 把日期编成自 **2001** 年起的秒数，pydantic 按 **1970**
解读——差 31 年。实测曾返回 200 并把 2026-09-19 存成 **1995-09-19**，
导出因全部落在窗口外而为空，**全程无任何报错**（PR #54 修）。
旧接口依赖 `.deferredToDate`，**不得全局改**，否则教师看板会坏。

### 10. 撤回者一律排除出导出
字典 §5：「正式策略冻结前，不自动将退出者资料加入新研究导出」。
你已确认的意向是保留退出前资料，但该意向**尚待学校要求核对**。
核对通过后需改 `export_research.py` 的纳入判定。

## 三、功能

### 11. 练习建议：只用整词证据，本轮不接 AI
- 分段 DTW **未经验证**，不作为音节级证据（字典 §9 的证据码是
  `verified_syllable_feature`，「如未实现经核验分析则不得传」）。
- 平调走向闸门是例外：明确计算、有阈值依据的整词特征。
- 教师提示与「这次的情况」分区显示；词条未核对则整块不渲染，
  **不得套用别词提示**。自由文本不默认具有词条提示。
- **本轮不启用 AI**，理由：
  1. 教师提示全为空，AI 只能拿到一个整词数值，据此「生成建议」等于编造教学内容，
     而字典明令「证据不足时…不生成虚假的个体纠音结论」；
  2. POST03 明确「不是 AI 建议专属评价」「不能仅凭本题得分宣称 AI 建议有效」，
     本轮设计上就没打算评估 AI 效果；
  3. 会新增一串上线前必须冻结的待办，而真正卡着的是教师核对与新旧用户识别。
- 记录结构已按支持 `ai_generated` 设计，将来接入不改表。
- **若将来启用**，输入白名单应为：目标词汉字与拼音（来自已核对词条）、
  目标声调序列、整词指标名与数值、是否通过。**不得上传**录音、F0 序列、
  Apple 标识、内部用户编号、问卷答案、国籍、语言背景、自由文本原文。

### 12. 积分规则（reward-1.0）
> **本轮保持关闭（2026-10-13）**：需求 2.3 版 §2「积分功能保持关闭」。
> 冻结配置时不传 `--reward-rule-version`，App 里不出现任何积分。下面的规则只在将来启用时适用。

- **每词首次说对 +1 分**；同词重练不再发，否则挑最容易的词就能刷分。
- **没有其它得分方式**。「连续练习 N 天」这类会引入行为激励，
  可能污染「自然使用」的观察——而本轮研究对象恰恰是自然使用模式。
- **本轮不做兑换/等级/成就**，理由同上。
- 由 `manifest.reward_rule_version` 开关：为空则整个功能关闭。
  启用方式：种子脚本加 `--reward-rule-version reward-1.0`。
- ⚠ 积分**不是**声调能力或教学效果指标，导出与论文中不得如此解读。

### 13. 学习记录：练习日志，不是能力报告
不写「进步/提升/水平」（有禁词测试）、不画趋势线、不算平均分、
列表不显示分数只显示通过与否。技术失败单独计数，不混进成绩列表——
它们的分数是 `-1` 哨兵。

### 14. 送气练习（关卡 1）：保留
需求十项未列它，但那更可能是疏漏——送气/不送气对立对摩洛哥阿拉伯语背景的
学习者有针对性。**已确定保留。**

审查时发现关卡 1 有与关卡 2、3 同类的问题，已修（见 PR）：
- 底噪校准失败与录音启动失败都只改状态、**无任何提示**（禁令 11，两处）
- 没有「没录上」判断：一帧都没收到时照样落一条 `triggerRate = 0` /
  `passed = false` 的记录，等于把麦克风故障算成「送气没做到」（禁令 9）

**已确定（2026-10-13，需求 2.3 版 §2）**：送气是补充产品功能，
**不进入本轮研究成绩与声调主分析**，不写研究表。业务记录按原有用途保留。

### 15. 不以新旧用户作为纳入条件
研究者已确认：**本轮不区分新旧用户**，所有符合其余条件者一律纳入。

此决定**取代**以下原文：
- 字典 §4：「本轮仅 new 可纳入」
- 字典 §14 纳入条件中的 `prior_use_status=new`
- 问卷 §6：「旧用户不纳入本轮统计」

实现方式是**去掉纳入条件**，而不是把所有人改写成 `new`：
`prior_use_status` 仍如实记录（未实现识别路径时为 `unknown`）。
把未核实、且对部分用户为假的断言写进数据列，比不筛选本身危害更大——
将来取数的人会把它当成已核实的事实。

⚠ **论文的样本描述必须写「未区分新旧用户」，不得写成「新用户样本」。**
导出的 `export_meta.json` 里有 `prior_use_policy` 字段写明此事，
并有测试断言 `inclusion_rule` 中不再出现 `prior_use_status=new`。

## 五、2026-10-13：需求 2.3 版带来的决定

### 16. 先有账号，再谈研究；研究是自愿入口，不是启动任务
首次路径：选语言 → 建立或恢复账号 → **直接进练习首页** → 有有效配置时在首页或设置里
自愿参加 → 知情说明 → 背景表 → 端侧判资格 → 服务端纳入 → 背景表可靠提交 → 练习前问卷邀请。

- 研究邀请原来排在登录之前，纳入接口拿到的是空账号，流程永远走不完。
- 麦克风权限改在**首次实际录音前**申请：那时语言已选好，用途说明看得懂；拒绝了也能浏览。
- 明确拒绝后首页不再出现邀请，设置里的入口一直在。
- 参与状态分五种：未询问 / 已同意未纳入 / 已参与 / 本轮未纳入 / 已退出。
  **服务端确认纳入之前不产生任何研究日志**，本地同意不等于已参加。

### 17. 两道门：「能不能产生新数据」与「能不能补传」
`ResearchGate.shouldCollect`（在采集中）与 `canUpload`（有身份、没退出）是两件事。
窗口关闭后不再产生新研究数据，但**窗口内合法产生、还没传上去的记录照样补传**，
服务端按**发生时间**判窗口，另记接收时间。原来只有一道门，窗口一关就把合法的待传记录清掉了。

### 18. 配置只下发给说明了自己版本的客户端
`/research/manifest/active` 必须带 `appVersion` 与 `build`；配置绑定构建号
（可用 `--compatible-builds` 追加修复版本）。**不带版本的旧构建拿不到配置**，研究路径对它关闭，
普通练习不受影响。这是有意的：旧构建（≤16）的事件名编码有误，放它进来只会产生被拒收的数据。

测试配置（`--test`）只下发给开发构建，其下参与者一律 `is_test=true`，正式导出默认排除。
材料还是草稿（同意文本含 `unpublished`、问卷含 `draft`、词条未全部 `approved`）时
**只能冻结成测试配置**，脚本拒绝冻结为正式配置。

### 19. 采集窗口由研究者指定，不再固定 14 天
`seed_manifest.py` 必须显式给出带时区的开始与结束时刻，左闭右开，UTC 存储。
开发不代选正式日期。导出支持 `--cutoff`：截止之后才**收到**的资料不进已定稿结果，
并在 `export_meta.json` 里记下数量。

### 20. 一份问卷从头到尾是同一个实例
邀请时生成实例编号并拍下快照（邀请时间、当时的合格次数、界面语言、表单与译文版本），
之后「稍后填写」「继续」「提交」「上传重试」都作用在这一个实例上。

- 状态：`invited` → `deferred` / `in_progress` → `declined` / `partial` / `complete`。
  服务端按等级只进不退：最终状态之后的重传幂等，不会被旧草稿覆盖。
- **服务端确认后才显示「已提交」**；只存在本机的如实显示「已保存，等待联网提交」。
- 前置问卷的时间定位只看**完成时间**相对首次练习开始的先后：之后才完成的是 `late_pre`；
  练习前已完成、只是离线晚传的仍是前置数据。接收时间不改变分类。
- 使用后问卷：5 次固定词条的有效结果**实际显示**后邀请，不要求通过，同词重录可累计，
  自由文本、自测、技术失败不计；按 `attempt_id` 去重。
  达到条件只是记下「该邀请了」，等用户**结束当前反馈**（换词、再练、离开）才弹出。

### 21. 退出研究、删除账号、再次参加
- 退出研究：端侧立刻停止采集并清空待传研究内容，只留一条待确认的退出指令；
  联网后**先**同步退出。账号与学习记录都还在。
- 删除账号：服务端在删除前**追加一条研究退出记录**（研究表的行保留，导出照常排除撤回者）。
- ⚠ **本轮不支持退出后再次参加**：服务端对已退出的参与者返回 409。
  重新纳入涉及退出前资料如何处理，属于第 10 条尚未审定的保留策略，不由开发决定。

### 22. 研究身份跟着账号走，不跟着设备走
`users` 表一台设备一行，所以两种情况都要处理：

- **同一账号换设备** → 还是同一位参与者（各设备行共用一个随机的 `account_id`）。
- **同一台设备换账号** → 是另一位参与者。设备行会被新登录的账号改写，
  所以「这个 Apple 账号对应哪个内部编号」单独存在 `account_links` 表里，
  不随设备行的改写而丢失；前一个人再登录回来，还是他原来那位参与者。

⚠ 这一条是界面全流程测试时**实测发现**的缺陷：最初内部编号只记在设备行上，
同一台模拟器上的第二个测试账号沿用了第一个账号的编号，被服务端当成同一位参与者，
连对方已提交的问卷状态都同步了过来。接口脚本测不出这个问题（脚本每次用新的设备号）。
修复后纳入**只认账号编号、不认设备号**，并补了四条回归测试。

研究状态（身份、计数、问卷草稿、待传队列）在本机也**按账号分开存**，切换账号互不可见。

已知限制：业务表（练习记录等）仍按设备建档。同一台设备换 Apple 账号后，
旧的业务记录仍挂在那台设备的行上——这是既有设计，不影响研究表。

### 23. 普通练习的记录与旧 `phase` 字段
新会话不再由「前测 → 训练 → 后测」驱动。研究表用 `task_type`：
`fixed_word`（普通固定词练习）/ `self_test`（可选自测）/ `free_text`。
旧业务表的 `phase` 保留兼容：普通练习写 `training`，自测写 `self_test`；
历史上的 `pretest` / `posttest` 行不再产生，也不迁移。本机记录版本升到 `schemaVersion = 6`。

每次真实录音一个新的 `attempt_id`，重录用 `retry_of_attempt_id` 关联；
取消（`cancelled`）、技术失败（`recording_failed` / `analysis_failed`）、
来不及收尾的中断（`interrupted_unknown`）分开保存，**没有成绩的一律为 NULL**。

### 24. ⚠ 字典增补：建议证据快照允许 `gate`
`research_advice_requests.evidence_snapshot` 允许的键增加 `gate`
（平调词走向闸门是否触发）。它是明确计算、有阈值依据的整词特征（第 11 条的例外），
不是未经核验的音节级诊断。详见 `docs/RESEARCH_DATA_DICTIONARY_DELTA.md`。

### 25. 界面：现代中式，白与墨为主体
以需求 2.3 版的配色参考图为视觉基线：白色与墨色主体，深松绿主操作，陶红与雾蓝点缀，
原创线描，首页 2×2 功能格。此前的列表方案、彩色游戏大厅方案与黑色主操作配色都已废止。

实现上的几处取舍（都是按文字规范办，而不是照搬样稿）：
- **曲线横轴不按音节分段、不标声调**。样稿在曲线下画了「hē / shuǐ」两段，
  但规范明确禁止暗示有经过验证的音节对齐——这里确实没有。
- **模块里不放宣传句和功能解释**，只有名称与线描。
- **线描由代码画出**（`Illustrations.swift`）：原创、矢量、随外观换色，没有位图资源，
  也没有取自任何第三方的图形。
- **参考曲线实线、学习者曲线虚线**，并有文字图例——两条线不单靠颜色区分。
- **录音键 72pt**（规范写「约 64pt」）：圆里要放图标和一个词的标签。
- **出错提示沿用陶红**做图标色，不另立颜色；陶红在浅灰底上不足 4.5:1，所以提示文字用主文字色。
- 颜色模式的四声用深松绿、雾蓝、赭、陶红，其中赭（`#86672D`）是规范色表之外补的一个，
  只用于三声标记。
- 所有色值集中在 `Theme.swift`，页面里不写色值；对比度由 `ThemeContrastTests` 实测。
